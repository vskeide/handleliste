## Follow-up refinement (local, awaiting push approval)

- Removed the separate static app header. The shared navigation/wake-lock provider
  persists in the app layout, while a reusable hamburger button appears on the right
  of each page's existing title row. The shopping list has one title/action row.
  The list's action buttons share a 44 px height and centered icons, aligning the
  middle ellipsis dot with the picker triangle tip. The options popover starts below
  the full button height.
- The dinner button now says only "Middagar" and uses the dinner icon. Its expandable
  meal rows render inline immediately below the list header, not in a bottom sheet.
  Opening the panel returns to the top of the list; the button toggles it closed.
- Removed the GPS "heime?" label; the away state retains the neutral icon styling.
- Store creation uses the same dark circular white-plus button as lists/dinners.
- The grocery input is transparent, borderless and without its own rounded/focus
  decoration; the outer search field clips its contents. Keyboard positioning now
  uses a bottom offset instead of translating a focused input's ancestor. This
  targets the overlapping light rectangle shown in the user's Edge Android image.
- The domain strip in that image sits between the page and the SwiftKey toolbar.
  It appears browser/keyboard-controlled; it was not reproduced or verified removed
  on a physical Android device. Do not claim the strip is fixed by the CSS change.
- All 68 tests and TypeScript pass. A 390 CSS-pixel browser fixture confirmed the
  title and hamburger share a row, the dinner panel begins at the header's bottom,
  there is no horizontal overflow, the focused input is transparent/contained, and
  the global full-screen menu/wake switch still opens. Fixture removed afterwards.

- Bottom navigation is replaced by a top hamburger menu. Its native full-screen
  dialog contains the same destinations and closes on selection or Escape. Fixed
  action bars elsewhere no longer reserve space for the removed bottom navigation.
- The shopping-list header no longer has the add (+) and map buttons. Search stays
  available at the bottom edge and moves above the on-screen keyboard.
- No most-bought chips appear on an empty list or when an empty field receives focus.
  Search results require typed input. Only household-owned meals are suggested in
  list search; starter dinners remain available in Middagar.
- Search has explicit search-field semantics and autocomplete disabled. This targets
  Edge Android treating the grocery field as a login/autofill field. The reported
  duplicated domain rows are browser-controlled and were not reproduced on a physical
  Android device; their disappearance must be checked on that phone after deployment.
- Picker mode uses a native top-layer dialog, body/root scroll locking, disabled touch
  panning and a drag threshold. Holding/dragging cannot reveal or scroll the background
  or pick an item accidentally. The add/search bar is unmounted while picking.
- The visible "Middagar i lista" button opens a list-specific dinner overview. Each
  dinner starts as one collapsed row; its arrow expands ingredient/removal actions.
  Existing contribution tracking and saved recipes are unchanged.
- "Hald skjermen på" in the hamburger menu explicitly requests the browser screen
  wake lock. It stays requested when the menu closes, reacquires on foreground return,
  reports support/errors, and releases on disable or unmount. Picker mode retains its
  automatic keep-awake behaviour using the same lifecycle-safe hook.
