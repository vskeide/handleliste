# Mobile interface simplification

Implemented locally, awaiting production-push approval.

- Bottom navigation is replaced by a top hamburger menu. Its native full-screen
  dialog contains the same destinations and closes on selection or Escape. Fixed
  action bars elsewhere no longer reserve space for the removed bottom navigation.
- The shopping-list header no longer has the add (+) and map buttons. Search stays
  available at the bottom edge and moves above the on-screen keyboard.
- No most-bought chips appear on an empty list or when an empty field receives focus.
  Search results require typed input. Only household-owned meals are suggested in
  list search; starter dinners remain available in Middagar.
- Search has explicit search-field semantics and autocomplete disabled. This targets
  Edge Android treating the grocery field as a login/autofill field. The reported
  duplicated domain rows are browser-controlled and were not reproduced on a physical
  Android device; their disappearance must be checked on that phone after deployment.
- Picker mode uses a native top-layer dialog, body/root scroll locking, disabled touch
  panning and a drag threshold. Holding/dragging cannot reveal or scroll the background
  or pick an item accidentally. The add/search bar is unmounted while picking.
- The visible "Middagar i lista" button opens a list-specific dinner overview. Each
  dinner starts as one collapsed row; its arrow expands ingredient/removal actions.
  Existing contribution tracking and saved recipes are unchanged.
- "Hald skjermen på" in the hamburger menu explicitly requests the browser screen
  wake lock. It stays requested when the menu closes, reacquires on foreground return,
  reports support/errors, and releases on disable or unmount. Picker mode retains its
  automatic keep-awake behaviour using the same lifecycle-safe hook.

Verification: all 67 tests, TypeScript, the production build and Nynorsk checking pass.
Targeted tests cover nested scroll-lock restoration,
cancelled/dragged picker gestures, late wake-lock completion, foreground reacquisition,
and refusals. A phone-sized Edge browser fixture confirmed typed-only search,
owned-meal results, full-viewport modal sizing, picker isolation, collapsed dinner rows,
and the actual wake-lock switch staying active after closing the menu. Native Android
keyboard/autofill and physical touch rubber-band behaviour still need a phone check.
The fixture was removed; no household data was changed.
